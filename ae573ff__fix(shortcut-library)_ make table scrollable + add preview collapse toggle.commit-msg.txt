fix(shortcut-library): make table scrollable + add preview collapse toggle

DetailPage wraps the component in a fixed 100vh viewport with overflow:hidden,
but shortcut-library used min-height:100vh on its root with no internal
scroll container. When a group had many shortcuts the table overflowed past
the viewport and got clipped, and there was no way to collapse the ~400px
keyboard preview out of the way.

Changes:
- Pin root to height:100vh + overflow:hidden so internal scrolling can take
  over (sidebar list, table viewport each become real scroll containers via
  flex:1 + min-height:0).
- Make .sl-sl-table__grid thead sticky so column titles stay visible while
  rows scroll.
- Add a collapse toggle to the keyboard preview header (down/up arrow with
  aria-expanded). Collapsed state hides the Keyboard component entirely
  and is persisted under a dedicated localStorage key
  (sl-shortcut-library:v1:previewCollapsed) so it does not get wiped when
  shortcut data is cleared.

Tests:
- shortcut-library-layout.test.ts (8): pins the CSS rules and TSX wiring
  via source-level assertions.
- shortcut-library-dom.test.tsx (4): renders the component in jsdom and
  asserts real computed styles (overflow, sticky, min-height) plus the
  toggle unmounts Keyboard and flips the section collapsed class.
- vitest.workspace.ts: react-components now runs under jsdom and picks up
  .test.tsx files.
