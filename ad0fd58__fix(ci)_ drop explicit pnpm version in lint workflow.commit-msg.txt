fix(ci): drop explicit pnpm version in lint workflow

action-setup@v4 already reads package.json#packageManager (pnpm@9.12.0).
Declaring both `version: 9` and the project field triggered
ERR_PNPM_BAD_PM_VERSION-style abort before pnpm install could run, taking
down the whole lint job. Let action-setup infer the version.

Also matches the intent of the post-cherry-pick root package.json which
intentionally tracks an exact pnpm version via packageManager, so CI stays
in sync if we later bump it there.
