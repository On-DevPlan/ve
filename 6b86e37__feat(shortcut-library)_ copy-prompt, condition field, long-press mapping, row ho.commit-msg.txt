feat(shortcut-library): copy-prompt, condition field, long-press mapping, row hover tooltip

Four product features added on top of the scroll/collapse fix:

1. Copy-format prompt rewritten to a self-contained LLM-friendly brief.
   Format includes role framing, field table, modifier/main-key table,
   three worked examples (basic, multi-group, with condition), and an
   explicit anti-patterns section. Replaces the previous 18-line template
   that drifted into generic TOML tutorials. IMPORT_FORMAT.md updated to
   match.

2. `condition` field on Shortcut. Stores an activation-condition note
   ("selected text", "macOS only", etc.) that the user can filter on but
   the runtime does not enforce. Wires through types.ts, useShortcuts CRUD
   + importGroups, ImportModal parser (new `condition = "..."` key,
   pending-state for order-independence like `desc`), ShortcutTable
   (new "条件" column at 22% width with inline edit input), and
   CapturePopover (optional input alongside combo).

3. Long-press mapping popup. Each keyboard key is now its own React
   component that owns a 250ms pointer-down timer; release before the
   timer fires does nothing (flash from the existing global keydown
   listener is unaffected). When the timer fires, the parent receives
   `onLongPress(code, rect)` and renders a portal-style floating panel
   listing every group that binds this code (`findBindingsByCode` walks
   the flat groups array; left/right modifier asymmetry is documented).
   Panel supports up to 5 hits + overflow; Esc or outside click closes.

4. Row-hover description tooltip. ShortcutTable fires a separate
   `onShortcutHover(shortcut, rect)` channel that does not interfere with
   the existing keyboard-highlight channel. The parent portals a small
   floating panel (combo chips + description + condition) anchored to
   the row's right edge, flipping to the left when the viewport is
   narrow. `pointer-events: none` keeps the tooltip from stealing hover.

5. (Defense) Flash throttle. The existing `flashKey` was protected
   against same-code strobing by a prev-set guard, but rapid cycling
   across codes (A→B→A) still re-fired timers on every event. Added a
   50ms per-code throttle (`flashLastAt` ref) so OS auto-repeat can't
   visually strobe the keyboard.

Tests:
- shortcut-library-features.test.ts: 14 source-level assertions
  covering the four features (FORMAT_PROMPT contents, condition data
  flow, long-press timer constants, portal usage, hover wiring).
- shortcut-library-dom.test.tsx + shortcut-library-layout.test.ts from
  the previous commit continue to pass.
