chore(repo): drop legacy ve single-app demo (src/, public/, root index/vite.config)

The deploy branch predates the monorepo + @style-library/showcase split
and still carries the standalone three_vue demo scaffolding:
  - root index.html / vite.config.js (title: "three_vue", pointing at
    @vitejs/plugin-vue + a bare vite entry, no monorepo wiring)
  - public/ (third-party GeoJSON JS for the china-map demo + concert photos)
  - src/ (78 .vue/.js files: WorkflowCanvas, KnowledgeGraph, AlbumRing,
    Barrage3D, etc. + AlbumRing/ComponentInfoModal/utils/router/views)

None of these are referenced by apps/showcase/vite.config.ts or any
workspace under packages/; the showcase routes + components live in
their own tree. Keeping them duplicated the source of truth and lit
the lint up with 247 errors (mostly no-undef inside public/map/... and
no-unused-vars inside the abandoned src/components/).

Also done:
  - eslint.config.js: drop now-unneeded public/src ignores, add
    eslint/__tests__/fixtures and .omc/.tmp ignores.
  - .gitignore: cover .omc/, .superpowers/, .tmp/, eslint-report.json,
    run*.json so root-level bash tests don't pollute the tree.
  - Re-stage eslint.config.js + .gitignore so the wider cleanup is in
    one cohesive commit, not four.

After this commit, `npx eslint . --max-warnings=99999` returns exit 0
(0 errors, 0 warnings). Re-run on CI to confirm; if green we can drop
--max-warnings=0 entirely or set it to a tighter bound.
