# Project Style — 项目风格规范

本项目(ve / wb monorepo)的风格规范**单一事实源**。每条规则包含:适用范围、判定方法、检测命令、修复方式、例外、存量政策。

> 新规则按序追加到本文末尾(见「后续规则」)。改规则 = 改本文件,不要散落到各处注释或 CLAUDE.md。

---

## 规则 1:禁止使用 emoji

### 适用范围(必须遵守)

emoji **不得**出现在:

- **代码**:标识符、字符串字面量、注释
- **提交信息**(commit message)
- **文档**:README、CHANGELOG、设计文档正文
- **UI 文案**:按钮、标签、菜单、标题、提示、占位符、空状态、卡片名
- **日志与错误信息**
- **文件名与目录名**

### 什么是 emoji(判定依据)

emoji = Unicode 下列图形字符区间(含 emoji 呈现):

| 区间 | 内容 |
|---|---|
| `U+1F300–1FAFF` | 杂项图形 / 表情 / 交通 / 补充图形(😀🚀🖼️🏆🤝🛫等) |
| `U+2600–26FF` | 杂项符号(⚠ ☀ ☂ ☎ 等) |
| `U+2700–27BF` | Dingbats(✎ ✅ ✗ ✏ ✂ 等) |
| `U+2B00–2BFF` | 杂项符号与箭头(⭐ ➡ 等) |
| `U+1F1E6–1F1FF` | 区域指示符(国旗字母对) |

**边界澄清(高频误判):**

- ✅ **允许** 的结构性/排版符:`→` `<-` `=>` `|` `*` `-` `>`(ASCII 与 U+2190–21FF 箭头,属排版符,非图形 emoji)。
- ❌ **禁止** 的装饰性图形:🖼️ 🚀 ✅ ❌ 🖱️ 🏆 📄 ⚠️(一律用文字替代)。
- **拿不准就判禁止**:只要它是"图形化的表情/物品/状态图标",就按 emoji 处理。

### 检测命令(已验证可用)

```bash
# 扫描项目源码,排除依赖/产物/克隆仓库
rg -n "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}\x{2B00}-\x{2BFF}\x{1F1E6}-\x{1F1FF}]" \
  -g '!node_modules' -g '!dist' -g '!.claude/repo/**' -g '!*.lock' \
  packages apps eslint

# 仅看提交信息里有没有 emoji
git log --format='%H %s' | rg "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]"
```

### 修复方式(常用替代)

| emoji | 文字替代 |
|---|---|
| ✅ / ❌ | 成功 / 失败(或 `[pass]` / `[fail]`) |
| ⚠️ | 注意 / 警告 |
| 🚀 | 启动 / 上线 |
| 🖼️ | 图片 / 封面 |
| 🖱️ | 鼠标 |
| 📄 / 📝 | 文档 / 备注 |
| 🏆 | 冠军 / 胜者 |
| ✎ ✏ | 编辑 |
| → ↗ | `→`(排版箭头,允许)/ "链接" |

### 例外(允许 emoji 的唯一情形)

**仅当 emoji 本身就是"被处理/被渲染的数据主题"时允许**,且必须在就近注释标明 `// emoji-as-data:`。典型:

- 文本排版/断行引擎的**测试样本**(其 emoji 是算法输入,不是 UI 装饰)——见 `packages/vue-components/src/pretext-text-layout/src/samples.ts` 的 🚀🌅。
- emoji 渲染 / 输入法 / 字体的测试夹具。
- 用户生成内容(UGC)的展示。
- **文档/示例的题材本身就是 emoji**(如本 skill 用 emoji 当作"被禁示例"展示,或 emoji 字体文档)。

> **反例**:即便在演示组件里,把 emoji 当**装饰**(可拖拽图形上的 🖼️、提示文案里的 🖱️、胜负标题里的 🏆)仍属禁止——那是 UI 文案,用文字替代。

### 存量现状(本规则立项时的盘点)

存量 emoji 广泛存在,**新代码必须遵守本规则**;存量按以下优先级择期清理:

| 位置 | 性质 | 处理 |
|---|---|---|
| `react-components/src/car-battle`(🏎️ 标题、🏆🤝 胜负) | 装饰 UI 文案 | 应清理 |
| `vue-components/src/china-map`(🖱️🛫 提示) | 装饰 UI 文案 | 应清理 |
| `react-components/src/shortcut-library`(✎ ✅ 📄) | 装饰 UI 文案 | 应清理 |
| `vue-components/src/pretext-text-layout/FlowPanel.vue`(🖼️) | 装饰 UI 文案 | 应清理(改为"图片"文字) |
| `manifest-generator`/`component-contract` 等注释里的 ⚠️ / ✗ | 源码注释 | 次优先清理(改为"注意"/"×") |
| `pretext-text-layout/src/samples.ts`(🚀🌅) | **排版数据主题** | **豁免**,保留 |

> 清理存量属于独立任务,不在本 skill 触发时自动执行;用户点名「清理 emoji」时再按上表逐项处理。

## 错误案例

| 错误操作 | 实际后果 | 正确做法 |
|---|---|---|
| 提交信息写 `fix: 🐛 修复登录` | 提交历史污染,部分终端/CI 日志乱码 | `fix: 修复登录` |
| 按钮文案用 🚀 启动 | 屏幕阅读器读"火箭表情",字体回退不一致,国际化丢字 | 纯文字"启动" |
| 一刀切 `rg` 删除所有 emoji | 误删测试样本里**作为数据**的 emoji,破坏 pretext 断行演示 | 先区分"装饰性"与"数据性",只删前者;数据性加 `// emoji-as-data:` |
| 把 `→` `<-` `=>` 当 emoji 删掉 | 误伤代码与技术文档的合法排版符 | 只禁图形 emoji(U+1F/26/27/2B 区间),保留 ASCII/箭头排版符 |
| 用 ✗ 表示失败写进错误信息 | ✗ 属 dingbat(U+2700–27BF),命中检测,字体回退可能变方框 | 用"失败"或 `[fail]` |

## 提交前检查清单

- [ ] 上方 `rg` 命令对新写/改动的文件**无命中**(或命中仅限标注 `emoji-as-data` 的数据例外)
- [ ] 提交信息(subject + body)无 emoji
- [ ] 新增 UI 文案(按钮/标签/标题/提示)为纯文字
- [ ] 新增/改动文档无装饰性 emoji
